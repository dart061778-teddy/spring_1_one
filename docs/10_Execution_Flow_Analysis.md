## 概要
本ドキュメントは、`spring_1_one` プロジェクトの全バックエンドコンポーネントおよび設定ファイルを統合し、アプリケーションの初期化からリクエスト処理に至るまでの全体的な実行フローとデータ連携構造を体系的にまとめたものです。

## 1. 開発環境の準備およびサーバー起動フェーズ (初回 & 起動時の流れ)
ユーザーからブラウザリクエストが送信される前に、開発環境(IDE)側でサーバーを立ち上げ、データベースおよびフレームワークを接続するプロセスです。

1. **プロジェクト環境の構築および依存関係ロード (`build.gradle`)**
   * `build.gradle` に記述されたライブラリ（Spring Web、MyBatis、Oracle JDBC `ojdbc11`、`orai18n` 等）を読み込みます。
   * Gradle Refresh を実行し、バックエンド駆動に必要な依存関係を自動ダウンロードしてプロジェクトに適用します。
2. **バックエンド & DB 環境設定情報の定義 (`application.properties`)**
   * Oracle DB 接続情報および MyBatis 設定（Mapper XML の位置、DTO エイリアスパッケージパス）を定義します。
   * コントローラーが返却する View ファイル名の前後に付与する接頭辞（`prefix`）と接尾辞（`suffix`）を事前に定義します。
3. **サーバー起動および Bean 登録 (`Spring1OneApplication`)**
   * アプリケーション起動時、`@SpringBootApplication` スキャン範囲内の `@Controller`、`@Mapper` インターフェース等を自動検出し、Spring Context (IoC コンテナ) にオブジェクト (Bean) として登録し、MyBatis プロキシオブジェクトを動的に生成します。

## 2. Webブラウザリクエスト処理フロー (リアルタイム動作順序)
ブラウザのアドレスバーにリクエストを送信した際に内部で実行されるバックエンドデータ処理フローです。

[1. Webブラウザ] ---> (リクエスト送信) ---> [2. MemberController]
                                                      ジュエリー
                                       (インターフェース呼び出し: DAO / Mapper)
                                                      ジュエリー
[5. 画面返却]   <--- (モデルデータ伝達) <--- [4. Oracle DB] <--- [3. MemberDaoInterface / memberMapper.xml]
                                 (member_이재열)    (SQL 実行 -> MemberDto マッピング)

1. **ユーザーからのリクエスト (Request)**
   * ブラウザから特定のエンドポイントへ HTTP リクエストを送信します。
2. **コントローラーによるマッピング受信 (`MemberController.java`)**
   * DispatcherServlet がアノテーション（`@GetMapping` / `@PostMapping` 等）を確認し、対応するハンドラーメソッドを実行します。
   * `@Autowired` で注入された DAO インターフェースのメソッドを呼び出します。
3. **DAO インターフェース & MyBatis SQL 実行 (`memberMapper.xml`)**
   * MyBatis 動的プロキシが `memberMapper.xml` の対応する SQL クエリ文を取得します。
   * `application.properties` に設定された DB 情報およびドライバを通じて Oracle DB へアクセスして SQL を実行します。
4. **DB データマッピングおよび Model 保持 (`MemberDto.java`)**
   * 取得されたデータが `MemberDto` オブジェクト単位で自動マッピングされます。
   * コントローラーがデータをリクエストスコープに保持させた後、ビュー名を返却します。
5. **レスポンス出力**
   * 事前設定されたパスに基づき、モデルデータを基に画面が構成されてブラウザ画面上に最終出力されます。

## 3. 主要要素の役割整理 (比喩解説)

| 構成要素 | 実際の役割 | 例え (レストランでの比喩) |
| :--- | :--- | :--- |
| **`MemberController`** | リクエストを受信し、全体のデータフローを制御 | 注文を受け取り料理全体を統括する **支配人 (マネージャー)** |
| **`MemberDaoInterface` / `memberMapper.xml`** | DB にアクセスして実際にデータを検索する persistence 層 | 倉庫から必要な食材(データ)を取ってくる **料理長** |
| **`MemberDto`** | 各層間でデータを保持して移動させる転送専用オブジェクト | 食材や料理を安全に乗せる **お盆 (トレー)** |
| **`Oracle DB (member_이재열)`** | 会員情報データが保管されているデータベース | 各種食材が保管されている **新鮮倉庫** |
| **`application.properties`** | DB 接続情報および View パスなど全体設定を管理 | レストランの運営ルールが書かれた **運営マニュアル** |

## 4. 技術的評価および改善ポイント (Refactoring Notes)
- **処理フローの可視化:** 各レイヤー（コントローラー、DAO、マッパー、DB）の連携順序が明確であり、トラブルシューティングや保守性が非常に高い構造となっています。
- **アーキテクチャの標準性:** 標準的な Spring Boot と MyBatis の組み合わせにより、拡張性の高い堅牢なバックエンド基盤を構築しています。
